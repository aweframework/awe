# Release notes for AWE 5 (unreleased)

✨ Features:
- A `select-multiple` or `suggest-multiple` criterion chooses how it shows its values with `display`, in both web engines: `display="summary"` keeps the field one line high with the chips that fit and a `+N` counter that opens the list of every value with a remove button each (the default of `select-multiple`), and `display="chip"` shows every value as a chip and lets the field grow (the default of `suggest-multiple`, which keeps its look). New attribute value `summary`; no new locale keys (#845).
- New access screen `access-admin`, opened by the *Screen access* option of the default menu: for a profile or a user (*See the access of*: a button group and its suggest) and an optional module, in one row, the whole private menu as a tree with the effective access of each option (*Allowed* / *Denied*), the layer that decides it (no rules, base profile file, module, global, profile or user rule, inherited from a parent), the own rule of the profile or user and inline warnings (allowed with the parent denied, redundant rule), with a search, quick filters with counts (*All*, *Allowed*, *Denied*, *With rule*, *Warnings*) and *Allow*, *Deny* and *Why?* per row (*Allow* and *Deny* are disabled when they change nothing). The *Why?* side panel shows the cascade of layers in order (module, base profile, global rule, profile rule, user rule, inheritance) with the one that decides, and every rule on the option, which can be switched or removed. Checking several options shows a bar to allow, deny or remove their rule (*Remove rule* only with a rule) after a preview dialog of the options and the users that change. *Compare* adds *Compare with*, one suggest of profiles and users grouped by type, and the access in the comparison with an *Only differences* filter: a profile simulates the subject with that profile (a user keeps their own rules), a user compares with that user's real access, without storing anything. *Review* lists, for every profile and user, rules on options that no longer exist, options allowed while their parent is denied and rules without effect, each with its fix. *Preview* shows the menu a profile or user sees in a module, with the hidden options and their reason. The access is computed with the same cascade as the menu of a signed-in user, the rules are the same `AweScrRes` rows changed through the audited restriction maintains (no migration), and there is no rule import or export: access that ships with the application goes in `profile/*.xml`. New locale keys in en-GB, es-ES and fr-FR (#791).
- Tree grids accept `multiselect="true"` in both web engines: a checkbox per row and a select-all checkbox in the header, with the selection bar of the flat grid; selecting a parent does not select its children (#791).
- A `button-radio` criterion with options (`initial-load="enum"` or `"query"`) renders one joined button group in the AngularJS engine, as in React, so one XML works in both engines, and shows its label above the buttons in the React engine, as in AngularJS, lined up with the criteria of its row; a `button-radio` criterion without options does not change (#791).
- A suggest groups its options when the rows of its query carry a `group` field (a locale key): one header per group, in the order of its first option, that cannot be chosen and that the arrow keys skip; the chosen option keeps its own label, and a suggest without `group` does not change. The *Compare with* suggest of `access-admin` groups its profiles and users this way (#791).
- The PrimeFlex spacing classes (`p-3`, `pt-5`, `mb-3`, `mx-auto`, `-mt-2`...) also work in the `style` of the AngularJS screens, with the same names and values as in React, so a screen gets the same spacing in both engines (#791).
- New button style `btn-tonal` (the soft primary tint, for an action that has to stand out without being the primary one) and card style `card-note` (an explanation instead of a metric: a soft band in the tone of its icon with the title and the description), in both web engines (#791).
- The footer of a React dialog (a child with the `modal-footer` style) sticks to the bottom after a separator line, and the body scrolls under it, as in the side panel (#791).
- An empty tree grid of the AngularJS engine shows the grid empty state (`empty-title`, `empty-text`, `empty-icon`) as the flat grid and the React tree grid, and draws its expand, collapse and leaf icon inside the `expand-column` cell (the `tree-id` column by default), indented by level, instead of in a separate column (#791).
- The saved searches of a window (`saved-searches="true"`) keep a layout and open the screen, in both web engines: the save dialog can keep the advanced criteria in use in the main filters (they are shown with the essential ones when the search is applied) and save a search without values, and a search can be the default of the user (*Open the screen with this search*, or *Set as my default* in *Manage searches*) or, set by a user who may publish, of a profile; the user's default wins. The server applies it before the initial load, only when the criteria kept for the screen bring nothing for the window and with the context variables winning, so the grid loads once, already filtered, and a chip names it. Reset returns to the default search and *Clear all* to the XML values; criteria the window no longer has are ignored. No new attribute. Migration `AWE_V1.6.1` adds `AweUsrWinCnf.DefSavSch` and `AweSavSch.Def` and makes `AweUsrWinCnf.AdvOpn` nullable; new locale keys `SCREEN_TEXT_SAVED_SEARCH_*` in en-GB, es-ES and fr-FR (#915).
- The saved searches of a grid (`saved-searches="true"`) have a default search, in both web engines: *Open the screen with this search* in the save dialog or *Set as my default* in *Manage searches* makes one the default of the user for the grid, and a user who may publish sets the default of a profile; the user's default wins. The server applies its column filters, sort, quick filter and search before the initial load, only when the session keeps nothing for the grid, so the grid loads once, already filtered and sorted, and a chip names it; *Clear all* of the column filter chips returns to the filters and sort of the XML and hides the chip, and the quick filter and the search keep their values. Columns the grid no longer has are ignored, a default of the window applies too, and the column layout is not part of it. No new attribute and no migration: it uses the storage of #915 with the grid id (#945).
- The side panel of the `theme-admin` screen shows a live preview of the theme being created or edited: a sample page (card, text with a link, tag, field and primary and secondary buttons) drawn with the primary colour, surface and mode of the panel while they change, before saving, and in the *System* mode with a *System* / *Light* / *Dark* switch. It is drawn in its own frame, so the theme of the application never changes. A custom hex is drawn once its palette arrives from the new `ThmPrvPal` query (service `themePreviewPalette`, `ThemeService.previewPalette`), and an invalid or empty hex keeps the last valid colour. New screen element `<theme-preview>`, in both web engines, and new locale keys in en-GB, es-ES and fr-FR (#949).
- The grid toolbar buttons are configurable in both web engines: the new grid attributes `show-columns-button` and `show-maximize-button` (default `true`) hide the Columns or the Maximize button, and `show-toolbar="false"` still hides both. The end buttons of the toolbar (*Group by*, *Saved searches*, *Columns* and *Maximize*) are icon-only by default, with their text as tooltip and accessible name: the new application property `awe.application.component.grid-toolbar-labels` (default `false`) sets it for every grid, set it to `true` to keep the labels, and the grid attribute `toolbar-labels` overrides it for one grid with `true`, `false` or a comma-separated list of the buttons that show their label (`group-by`, `saved-searches`, `columns`, `maximize`), e.g. `toolbar-labels="saved-searches"`. A grid with a hidden Columns button ignores the column layout stored by its users: it is neither applied nor saved.

🐛 Bug fixes:
- The colour picker of a `color` criterion or a colour grid column opened past the right edge of the window when the swatch was near it (the *Custom primary* of the theme side panel) and added a horizontal scrollbar: it is now shifted to the left until it fits, in both web engines (#949).
- A tree grid of the AngularJS engine reloaded with fewer rows (a quick filter, a search) kept the rows of the previous load (#791).
- The arrow keys on a `radio` or `button-radio` grid column of the AngularJS engine threw `$rootScope:inprog` (#791).
- An empty `status-field` cell of the AngularJS engine painted a dot without text, and the rows of a tree grid were bold (#791).
- The header of a side panel whose `header-grid` is a tree grid did not show the selected row in the AngularJS engine (#791).
- A `load-all` tree grid of the React engine showed a paginator and split its rows in pages (#791).
- The React engine ignored the per-row dependencies of the buttons of a grid column (`currentRowValue`), so a row button stayed enabled where AngularJS disabled it, and found the rows of a tree grid by `id` instead of by its `tree-id` (#791).
- The match highlight of the AngularJS select and suggest lists underlined the searched text, so a searched space showed as an underscore: it is now semibold, without underline (#791).
- New `queue-admin` screen, opened by the *Message queues* option of the default menu, built like `email-server-admin`: a grid of JMS queues with a search by alias, quick filters with counts (*All*, *Active*, *Inactive*), an edit button and a menu per row (edit, duplicate, delete), a selection bar and a side panel that creates and edits a queue (alias, description, queue type, destination, connection type, broker, user and password, state) with one action and shows the state of the queue in its header. It reuses the queue queries and maintains (`QueLst`, `QueNew`, `QueUpd`, `QueDel`, `QueAlsUni`) and adds `QueStaCnt`, `QueStaCntAct` and `QueStaCntIna` for the quick filters. The stored password is never shown: it is only written when the user types a new one.
- New `email-server-admin` screen, opened by the *Mail servers* option of the default menu, built like `database-admin`: a grid of mail servers with a search by alias or host, quick filters with counts (*All*, *Active*, *Inactive*), an edit button and a menu per row (edit, duplicate, delete), a selection bar and a 480px side panel that creates and edits a server (alias, host, authentication with its user and password, state select) with one action and shows the state of the server in its header. It reuses the mail server queries and maintains (`EmlSrvLst`, `EmlSrvNew`, `EmlSrvUpd`, `EmlSrvDel`, `EmlSrvNamUni`) and adds `EmlSrvStaCnt`, `EmlSrvStaCntAct` and `EmlSrvStaCntIna` for the quick filters. The stored password is never shown: it is only written when the user types a new one.
- New sequence administration screen `sequence-admin`, opened by the *Sequences* option of the default menu, built like `site-admin`: a grid with the name, the value and the state of the sequences, a search by name, quick filters with counts (*All*, *Active*, *Inactive*), an edit button and a menu per row (edit, delete), a selection bar to delete and a side panel to create and edit a sequence. The editable grid of the `AweKey` screen and its multiple maintain are replaced by one maintain per action (`AweKeyNew`, `AweKeyUpd`, `AweKeyDel`): the name of a sequence is its primary key and the panel keeps it read-only when editing, so `AweKeyUpd` takes the sequence of the selected row (`KeyNam.selected`) and writes only its value and its state. `AweKeyLst` returns the state of each sequence and filters by the search text and by the state, and `KeyStaCnt` counts the quick filters. New locale keys in en-GB, es-ES and fr-FR.
- New application parameter administration screen `application-parameter-admin`, opened by the *Application parameters* option of the default menu, built like `sequence-admin`: a grid with the name and its description, the value, the category (general, security or reports) and the state of the parameters, a search by name or description, quick filters with counts, an edit button and a menu per row, a selection bar to delete and a side panel to create and edit a parameter with the name, the category, the value and the description, which reloads the application properties after saving (`refreshDatabaseProperties`), as the screen it replaces. The editable grid of the `AweAppPar` screen is replaced by `AweAppParNew`, `AweAppParUpd` and `AweAppParDel`, and `AweAppParLst` returns the state and the category of each parameter and filters by the search text and by the state; `AppParStaCnt` counts the quick filters.
- New site administration screen `site-admin`, opened by the *Sites* option of the default menu, built like `profile-admin`: a grid with the avatar, name, order and state of the sites, a search by name, quick filters with counts (*All*, *Active*, *Inactive*), an edit button and a menu per row (edit, duplicate, delete), a selection bar to delete and a side panel to create and edit a site that holds **inside it** the grid of the modules and databases of the site (`SitModDbsLst`), so the site and its rows are saved with one action; the panel is 640px wide, in pixels because the root font size differs between the engines, and the header of the panel shows the site with its state. It reuses the site queries and maintains (`SitLst` returns the avatar and the state of each site and `SitStaCnt` counts the quick filters; the new `QryLstModDbsBySitAdm` returns the modules of a site with the site of each row as `IdeSitRow` and its order as `SitModOrd`, so no column clashes with the `Ord` and the `IdeSit` of the site in the grid of the screen; `SitUpd` takes the site of its module rows from the grid, accepts the one element list of the selected rows and reads the order of a row from `SitModOrd`, and `SitNew` reads the order of the new site from `OrdCrt`).
- New module administration screen `module-admin`, opened by the *Modules* option of the default menu, built like `site-admin`: a grid with the avatar, name and initial screen, the number of profiles, users and sites, order and state of the modules, a search by name, quick filters with counts (*All*, *Active*, *Inactive*), an edit button and a menu per row (edit, duplicate, delete) and a selection bar to delete. A 640px side panel creates and edits a module in three tabs: *General* (the module, chosen among the modules of the menu, its initial screen, order and state), *Access* (the profiles and the users that can enter it, each one an editable grid) and *Sites and databases* (the database of the module on each site, the same rows the sites screen edits); the module and its three grids are saved with one action (`ModNew`, `ModUpd`). The panel always opens on *General*. New queries `ModLstAdm` (with the counts), `ModStaCnt`, `ModStaCntAct`, `ModStaCntIna` and `ModNamUni` (a duplicated name is refused); `ModLst` does not change.
- Every grid in both web engines has a toolbar with a Columns dialog (show, hide and reorder the columns, nested under their group header, with Restore default, Cancel and Save) and a Maximize button. The layout is stored per user in the new `AweUsrGrdCnf` table (Flyway `AWE_V1.3.1`) and follows the user across devices; columns never leave their group header and the group headers are computed from the visible columns of the group, which also fixes the misalignment of the React headers when a grouped column is hidden. A grid opts out with `show-toolbar="false"` (#813).
- New `date-range` criterion in both web engines: a start and an end date in one criterion (the end cannot be before the start), sent to the server as two parameters (`<id>.from` and `<id>.to`), with configurable quick presets (`presets="1M,3M,YTD,12M,3Y,ALL"`) that are translated and cleared when a date is edited (#839).
- Client actions `move-row-top`, `move-row-up`, `move-row-down` and `move-row-bottom` move the selected row of an editable grid in both web engines, with `Alt+ArrowUp`, `Alt+ArrowDown`, `Alt+Home` and `Alt+End` as keyboard shortcuts. The moved rows keep their order in the data the grid sends on save, and the `MoveRowActionBuilder` builds the actions on the server (#842).
- Grids can group their rows by one or more columns in both web engines (`group-by="region,country,city"`): each group shows a row with its value, its row count and the aggregates of the columns with `summary-type` (sum, avg, max, min), collapses and expands, and ends with a subtotal row (`group-subtotals="false"` hides it), with per-level classes `grid-group-level-{n}` and `grid-subtotal-level-{n}`. The toolbar adds Expand all, Collapse all and, with `group-selector="true"`, a Group by panel that changes the levels at runtime. Sorting by an aggregated column orders the groups by it, and the `show-totals` footer stays the grand total. A grouped grid loads every row (as `load-all`) and does not paginate, so expanding, collapsing and regrouping need no server call; grouping is ignored on tree, editable, `send-operations`, `move-rows` and `row-detail` grids, and grids without the attributes render as before (#833).
- Grid columns can show a secondary line under the main value (`secondary-field`), a status with a dot of a tone plus the text (`status-field`, tones `success`, `warning`, `danger`, `info` and `neutral`, an unknown one is `neutral`) or a list of chips (`chips="true"`, `chip-separator`, and `max-chips` collapsing the rest into a "+n" chip that lists them), in both web engines, without HTML in the data: values always render as text and rows grow to fit. Sorting, filtering and export use the main value; `export-secondary="true"` adds the secondary value as its own export column titled with `secondary-label`. Grids without the attributes render as before (#832).
- `progress` grid columns can draw a light data bar behind the number in the React engine: `bar-min` and `bar-max` set the scale (4.13 with `bar-max="40"` fills 10.3 %), a `bar-min` below zero draws an axis on the zero and negative values to its left in the negative colour, `bar-second-field` adds a second value on the same scale (for example a target) as two thin rounded bars, `bar-stack-fields` draws stacked segments and `bar-leaf-only="true"` draws the bar only on the leaf rows of a tree grid. Screen readers get the value (`role="meter"`) and print and export write the number. Progress columns without the attributes render as before; the AngularJS engine ignores them (#831).
- Grid columns can wrap their text over several lines with `wrap="true"`, or limit it to a number of lines with `max-lines="N"` (line N ends in an ellipsis and the full text shows on hover and on keyboard focus), and the row grows to fit it, in both web engines. Without the attributes grids render as before; `wrap` and `max-lines` are also in the `ColumnBuilder` setters. In the React engine, text cells and headers cut by their width show the full value as a tooltip. In the AngularJS engine a grid with wrapping columns renders every row of its page (no virtualization), uses `row-height` as the minimum row height and keeps single-line rows when it has frozen columns or is a tree (#825).
- Integration tests of MySQL, PostgreSQL, SQL Server and Oracle (and their Flyway variants) run their database in a Testcontainers container, locally and in CI, with the image of each engine pinned in `awe-testing-images.properties` (#764). Docker is the only requirement; no database server or connection settings are needed.
- `awe-testing` ships `@AweDatabaseTest` and `TestDatabase` to choose the database of a Spring test class.
- `awe.security.sso.local-login` (default `true`) switches off the local username and password login when SSO is enabled, and `awe.security.sso.break-glass-users` lists the users that can still sign in locally in an emergency from `/screen/public/signin-local`; each use is logged at `WARN`. The sign-in screens of both clients hide the local form, and the three login entry points (`/action/login`, `/api/authenticate`, standard form login) refuse the other users with the same response as a wrong password (#767).
- OIDC back-channel logout: with `awe.security.sso.back-channel-logout.enabled=true` (default `false`) the identity provider can end AWE sessions by posting a logout token to `/logout/connect/back-channel/{registrationId}`. Each matching session goes through the AWE logout handlers (session data, websocket connections, HTTP session). The OIDC session registry is in memory by default and can be replaced with an `OidcSessionRegistry` bean; `awe.security.sso.back-channel-logout.logout-uri` sets the internal logout address, bounded by `connect-timeout` (default `2s`) and `read-timeout` (default `5s`) (#767).
- `awe.security.sso.roles-claims` (default `realm_access.roles`) sets the ID token claims that carry the SSO roles, so Keycloak client roles (`resource_access.<client>.roles`) and Microsoft Entra ID app roles (`roles`) work without a custom converter. `awe.security.sso.require-role` refuses an SSO login whose roles map to no AWE profile (fail closed, localized error page in en-GB, es-ES, fr-FR); when not set it is on with `local-login=false` (IdP-first) and off otherwise, so `require-role=false` is the explicit opt-in to the default role fallback. Existing users are refused too: their stored profile is not a fallback (#767).
- A user whose password expired (`PwdExp`) is guided from the login to set a new one in both web engines, without getting a session with the expired password, and then signs in with the new password. The expired-password message is localized (en-GB, es-ES, fr-FR) and `POST /api/authenticate` answers `401` with a localized message and the code `PASSWORD_EXPIRED` (#849).
- New `awe-observability-spring-boot-starter`: one dependency gives health checks (`aweDatabases` for every database alias, `aweQueue` for JMS), Micrometer metrics and traces for every query, maintain and action execution (timers `awe.query`, `awe.maintain` and `awe.action`, tagged with the XML id, the outcome and, for queries, the connector) and a reference Grafana dashboard. It is opt-in (applications without the dependency do not change) and it is built on a new `ExecutionObserver` extension point of AWE that does nothing unless a bean of that type exists (#780). See the Observability guide.
- New `map` screen element in both web engines: a Leaflet map with OpenStreetMap tiles that shows the rows of a query as markers (`latitude`, `longitude`, `marker-label`, `zoom`, `center-latitude` and `center-longitude`), selects the row of the clicked marker and launches its dependencies. The `polyline` client action draws a route over it. `awe.application.map.tile-url` sets another tile server. The legacy AngularJS `aweMap` directive and the vendored `angular-google-maps`, never bundled, are removed (#798, #882).
- New `<side-panel>` container in both web engines: a dialog anchored to the left or right edge of the screen (`position`) up to a maximum width (`max-width`, default `40rem`), with a header, a scrollable body and a footer. It opens and closes like a dialog (`dialog`, `close`, `close-cancel`, `on-close`, `deferred`), also closes with its close button, Esc or a click outside, keeps the focus inside while it is open and gives it back to the control that opened it; `SidePanelBuilder` builds it on the server (#843).
- The grid attribute `columns-panel` opens the Columns of the grid toolbar as a popover anchored to the Columns button (`popover`, the default), as a modal dialog (`dialog`) or as a side panel anchored to the right edge (`side-panel`), in both web engines; `awe.application.component.grid-columns-panel` sets it for the grids that do not define it (#843).
- New `<popover>` container in both web engines: a dialog anchored to a control of the screen (`anchor`), opened on one of its sides (`position`: `bottom` by default, `top`, `left` or `right`) up to a maximum width (`max-width`, default `20rem`), with a header, a body and a footer. It opens and closes like a dialog (`dialog`, `close`, `close-cancel`, `on-close`, `deferred`), also closes with its close button, Esc or a click outside (a click on its anchor closes it without opening it again), keeps the focus inside while it is open and gives it back to the control that opened it; `PopoverBuilder` builds it on the server (#843).
- New `<card>` screen element in both web engines: a metric tile with a title, a value with its unit, an icon, a change (`delta`) with its trend arrow and a caption, a sparkline of a series of numbers (`sparkline`, `sparkline-type`), a progress towards a `target` drawn as a bar or a gauge (`progress-style`), a description, a footer and a body with any child component (a chart, a grid...). Its attributes are static values and, with `initial-load="query"`, the first row of the query overrides them with fields named in camelCase (`value`, `delta`, `deltaUnit`, `tone`...). The tone of the change follows `tone`, then `trend`, then the sign of the delta, with `good-trend="down"` for figures where going down is good news, and it is told by arrow and text, not colour alone. The `awe-card-grid` class lays out cards as a responsive grid (`awe-card-wide` makes a card take two columns), and a card refreshes like any component (`filter`, dependencies, `autorefresh`) (#899).
- A card can show one status chip at its top right, before the icon or the delta, a tag with a dot (`chip`, coloured by `chip-tone`: `success`, `warning`, `danger`, `info` or `neutral` by default), in both web engines. The query can return `chip` and `chipTone`, so the status changes when the card is refreshed (#836).
- Grids with the new optional attribute `move-rows="true"` show a narrow leading column with a grip: dragging a row by its grip (move cursor on hover, a drop line before or after the row under the pointer) moves it to that position in both web engines, with the same change as the `move-row` actions. The Alt+Arrow shortcuts also work with `move-rows`, without `editable`; tree grids and grids without the attribute do not change (#888).
- New user administration screen `user-admin`, opened by the *Users* option of the default menu: a grid with the avatar, name, login and email, profile, state and two-factor state of the users, a search, quick filters with counts, an edit button and a menu per row, a selection bar and a side panel to create and edit users with an identity header. It reuses the user queries and maintains; the new `UsrUnl` maintain unlocks the selected users and audits it, and `audit-user-update` accepts several users. New generic pieces for any screen, in both web engines: `<quick-filter>` and `<search>` in the grid toolbar, `avatar-field`/`avatar-tone-field` and `icon-field` on grid columns, `selection="true"` grid buttons shown in a selection bar, a side panel identity header (`header-grid` and `<header-tag>`), icon-only buttons (`no-label`), `btn-*` button styles in React, section titles with an icon (`tag` `icon`, `awe-form-section-title`), a `switch` style for checkbox criteria in AngularJS and a show/hide button on password criteria (#793).
- New profile administration screen `profile-admin`, opened by the *Profiles* option of the default menu, built like `user-admin`: a grid with the avatar, name, acronym and theme, initial screen, file restriction and state of the profiles, a search by name, acronym, theme or initial screen, quick filters with counts (*All*, *Active*, *Inactive*), an edit button and a menu per row, a selection bar to delete and a side panel to create and edit profiles with an identity header. It reuses the profile queries and maintains (`ProLst` returns the new fields, `ProStaCnt` counts the quick filters) (#793).
- New theme administration screen `theme-admin`, opened by the *Themes* option of the default menu, built like `user-admin`: a grid with a circle of the primary colour, name, primary · surface (the palette or the hex), mode and state of the themes, a search by name, primary or surface, quick filters with counts (*All*, *Active*, *Inactive*), an edit button and a menu per row, a selection bar to delete and a side panel to create and edit themes (palette selects with a colour picker for a custom colour, mode and, when editing, the *Active* switch) with an identity header. It reuses the theme queries and maintains (`ThmLst` returns the new fields, `ThmStaCnt` counts the quick filters) (#793).
- Grid columns can show a decorative circle of a colour of the row before the main value, in the place of the avatar (`swatch-field`), and the side panel identity header too (`header-swatch-field`), in both web engines: an AWE 5 palette name (drawn with its `500` shade of the design tokens) or a `#RGB` / `#RRGGBB` hex; any other value draws no circle, so a row can never inject CSS. The themes screen uses it for the primary colour of each theme (#793).
- New database administration screen `database-admin`, opened by the *Databases* option of the default menu, built like `user-admin`: a grid with the avatar, alias and description, environment, database type and state of the connections, a search by alias, description, connection or user, quick filters with counts (*All*, *Active*, *Inactive*), an edit button and a menu per row, a selection bar to delete and a side panel to create and edit connections (connection, credentials with the password written only when typed, description, *Active* switch and the read-only list of its sites and modules, edited in a wide dialog over the panel and saved with the connection) with an identity header. It reuses the database queries and maintains (`DbsLst` returns the new fields, `DbsStaCnt` counts the quick filters) and reloads the database selector after saving or deleting (#793).
- New client action `copy-rows` in both web engines: `<button-action type="copy-rows" target="ReadOnlyGrid" value="EditableGrid"/>` replaces the rows of a grid with a copy of the rows of another one (without its deleted rows), each shown column with the cells of the shown column in the same position and the select cells with the text of their option, without marking the grid as changed. It shows a read-only list of a child grid edited in a dialog, as the sites and modules of `database-admin`; a side panel no longer takes the Tab key of a dialog opened over it (#793).
- The `awe-section-title` style turns a tag into a section title in both web engines: a small uppercase muted label followed by a line that fills the row (`<tag type="h3" style="awe-section-title" label="..."/>`) (#910).

**[HAS IMPACTS]** Changed:
- The `screen-access` option (*Screen access*) of the default menu and of the archetypes opens the new `access-admin` screen instead of `ScrAccRes`, and the test applications no longer list the `screen-access-upgraded` and `menu-access` options (#791).
- `QueUpd` writes the password of a queue only when a new one is typed, as `EmlSrvUpd` does: its first update wrote the empty value the panel sends when the field is left empty, so editing a queue erased the stored password.
- The calendar of the date criteria and of the date columns of the React engine is drawn at the size of the design system prototype: a day of 32px (28px in the compact density) with a 2px gap between the days, the rounded square of the prototype instead of the circle, the days and the week labels in the small size of the type scale, and a panel header and footer with the padding of the prototype. The 40px day with 8px cells it had made the grid wider than the panel that holds it. The AngularJS engine keeps its calendar.
- The *Message queues* option of the default menu and of the archetypes opens the new `queue-admin` screen instead of `Que`, and those menus no longer list the hidden options of the deprecated queue screens (`new-queue`, `update-queue`).
- The *Mail servers* option of the default menu and of the archetypes opens the new `email-server-admin` screen instead of `EmlSrv`, and those menus no longer list the hidden options of the deprecated mail server screens (`new-email-server`, `update-email-server`).
- The page of a horizontal tab starts below the list of tabs with the layout gap in the React engine, as in the AngularJS engine: the first title of the page no longer touches the line under the tabs.
- A button of a grid row (the pencil of a row) in the AngularJS engine launched its actions twice when selecting its row ran other actions: the actions that disable the buttons re-launched the click that was still pending, so a side panel opened by the button reopened after it was saved.
- The AngularJS engine has the `height-xl` container class (450px minimum height), as the React engine.
- The paginator of a grid in a narrow container (a side panel, a dialog) keeps the navigation and drops what does not fit, in this order: the range of the rows shown, the word that labels the page input and, below 42rem, the rows per page. The arrows, the page input and its total remain, so the paginator fits in one line instead of wrapping under the grid buttons.
- The *Modules* option of the default menu and of the archetypes opens the new `module-admin` screen instead of `Mod`, and the menus no longer list the hidden options of the deprecated module screens (`new-module`, `update-module`, `view-module`). The new screen has no theme: the theme of a module and the theme of a user in a module were stored but never applied (the theme of a user comes from the user and, when it has none, from the profile). The `IdeThm` fields of `ModNew` and `ModUpd` are optional, so a save without a theme keeps the stored one (the deprecated `ModNew` and `ModUpd` screens no longer clear it when the theme is left empty), and `QryLstUsrByMod` lists the users of a module that have no theme. `ModDel` also reads the selected modules from `IdeModSel`.
- The *Sites* option of the default menu and of the archetypes opens the new `site-admin` screen instead of `Sit`, and the menus of the archetypes no longer list the hidden options of the deprecated site screens (`new-site`, `update-site`, `view-site`).
- The *Users* option of the default menu and of the archetypes opens the new `user-admin` screen instead of `Usr`. Grid columns with `component="button"` are action columns: they are no longer listed in the Columns of the grid toolbar nor printed or exported, whatever their `printable`. The React engine now honours `printable` when printing, as the AngularJS engine, and the server leaves out `printable="false"` columns. A button of a grid cell selects its row before its actions in both engines (#793).
- The *Profiles* option of the default menu and of the archetypes opens the new `profile-admin` screen instead of `Prf`. `ProUpd` no longer writes the profile identifier (it only audits it), so the identifier can come as a one element list from a grid (#793).
- The *Themes* option of the default menu and of the archetypes opens the new `theme-admin` screen instead of `Thm` (#793).
- The *Databases* option of the default menu and of the archetypes opens the new `database-admin` screen instead of `Dbs`. `DbsUpd` takes the connection of every site row from `IdeDbs.selected` when it comes, so the grid can send `IdeDbs` as a one element list (#793).
- The menus of the archetypes no longer list the hidden options of the deprecated user, profile, database and theme screens (`new-user`, `update-profile`, `view-database`...): their *Users*, *Profiles*, *Databases* and *Themes* options open only the new screens (#793).
- The Columns of the grid toolbar open by default in a popover anchored to the Columns button, in both web engines: no backdrop, so the grid stays visible while the changes apply live. The new `columns-panel` value `popover` is the default of the grid attribute and of `awe.application.component.grid-columns-panel`; `dialog` and `side-panel` keep working. The three containers share the content of the design system prototype: the "N of M visible" counter in the header, a close button (x) that keeps the changes, and *Restore default*, *Cancel* (undoes the changes since the Columns were opened, or since the last restore, and closes them) and *Save* (closes the Columns once the layout is saved; they stay open when it fails). *Show all* is removed. This changes the default look of every grid toolbar: set `awe.application.component.grid-columns-panel=dialog` to keep the modal dialog. In `awe-testing`, `clickGridColumnsCancel` is new, `clickGridColumnsSave` waits for the Columns to close and `clickGridColumnsShowAll` is deprecated (check each hidden column with `showGridColumn`) (#904).
- When several SSO roles carry the `filter-authority-prefix`, the profile is the first name in alphabetical order that exists as an AWE profile instead of the first role of an unordered set; roles equal to the prefix are skipped instead of hiding the others (#767).
- A password set by an administrator counts as expired while `PwdExp` is set, so the user changes it at the first login (#849).
- A query `function` or `cast` that the engine does not support makes the query fail with an error that names the query, the field and the value, instead of silently becoming `SUM` or `INTEGER`; `LENGTH` is a field function and is no longer accepted as a `totalize` function (#853). Check the queries for values outside the documented lists (for example `COUNT`, whose real name is `CNT`). Applications that extend `SQLBuilder` and override `getExpressionFunction` or `getExpressionCast` must use the new signatures, which receive the field name and declare `AWEQueryException`.
- The `DbsLst` query no longer returns `DbsPwd`: the client got the encrypted password of every database connection although no screen shows it. Copying a connection in the deprecated `Dbs` screen leaves the password empty instead of filling it with the encrypted one, which the copy encrypted again. A screen of your own that reads `DbsPwd` from `DbsLst` must stop doing it (#793).
- Password change and user information definitions now require a session (#852). The `ChdPwd` maintain target changes the password of the logged in user only; the public change-password screens (`ChdPwdPub`, `change-password`) use the new public `ChdPwdPub` target, which changes the password only when the current password (`OldPas`) matches. The `UsrInf`, `AutUsr`, `GetEmlSrvByOpe` and `JmsConnections` queries and the `UpdCntLog` and `UpdPwdLck` maintain targets are no longer public, and `UsrInf` and `AutUsr` no longer return password fields. Applications that launched any of them without a session must sign the user in first (or use `ChdPwdPub` with the current password).
- The *Sequences* and *Application parameters* options of the default menu and of the archetypes open the new `sequence-admin` and `application-parameter-admin` screens instead of `AweKey` and `AweAppPar`. The multiple maintain of the sequences screen is renamed `AweKeyMul` (as `AweAppParMul`), so `AweKeyUpd` names the update of one sequence: an application that overrides it must use `AweKeyMul` for the editable grid.
- When an action with `check-records-saved` is blocked because an editable grid has a row that is still being edited, both web engines tell the user where that grid is: the tabs, wizard steps and accordion items that hide it are opened and the row being edited is scrolled into view, and the tab header and the wizard step that hold the grid carry the same error indicator as an invalid field while the grid has unsaved rows, until the row is saved or cancelled. The warning message does not change, and a screen without hidden content keeps the warning alone, as before (#918).
