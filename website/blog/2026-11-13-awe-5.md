The AWE framework team is proud to announce **AWE 5.0**, the biggest release of the framework so far: a new platform
(Java 21, Spring Boot 4.1, Jackson 3), a new design system shared by both web engines, the React engine as the engine
for new work, and a new generation of administration screens, grids and security tools.

Before upgrading, read the [AWE 5 migration guide](/docs/guides/v5-migration): it lists everything an AWE 4
application has to review, with the symptom, what to do and where to read more.

<!-- truncate -->

## A new platform

| | AWE 4 | AWE 5 |
|---|---|---|
| Java | 17 | **21** |
| Spring Boot | 3.5 | **4.1** (Spring Framework 7, Spring Security 7, JUnit 6, Flyway 11) |
| Jackson | 2.x | **3** (`tools.jackson`) |
| React client | `2.x`, own version line | Same version as the framework, React 19 |
| Charts | Highcharts | **Apache ECharts** in both engines |

The React client (`awe-react-client`) now follows the version of the framework, so one number tells you what you run.
Its heavy packages (charts, editors, maps) load on demand, and the AngularJS client no longer ships the JavaScript of
Bootstrap 3.

## The AWE 5 design system

Both web engines share one design system: Inter typography, Lucide icons, light and dark modes, comfortable and compact
density and themes made of a **primary colour** and a **surface**. A theme is a palette name or a hex colour, and the
whole scale is generated from it with readable contrast. The new `theme-admin` screen shows a live preview of the theme
while you edit it.

The [design system](/docs/design-system/overview) is documented on this site with live components.

## React, the engine for new work

The React engine is the AWE 5 engine: new components land there. The AngularJS engine keeps working, so your
applications run as they are, but it is frozen: it gets fixes, not new components. One XML screen still works in both
engines.

## New administration screens

The default menu opens a new generation of administration screens, all built the same way: a grid with search and
quick filters with counts, row actions, a selection bar and a side panel to create and edit.

- `user-admin`, `profile-admin`, `site-admin`, `module-admin`, `database-admin`, `theme-admin`
- `email-server-admin`, `queue-admin`, `sequence-admin`, `application-parameter-admin`
- `access-admin`: the whole menu as a tree with the effective access of each option for a profile or a user, the
  layer that decides it, *Why?*, *Compare*, *Review* and *Preview*.

The old screens are deprecated and will be removed in 5.1.0.

## Grids that do more

- A toolbar on every grid: a **Columns** dialog (show, hide and reorder, stored per user) and **Maximize**.
- **Group by** one or more columns, with subtotals and aggregates.
- **Saved searches**, with a default search per user or per profile.
- Richer cells: a secondary line, a status with a coloured dot, chips, data bars and wrapping text.
- Tree grids with multiple selection, and rows that move with the keyboard.

## New criteria and elements

- `date-range` with quick presets (`1M`, `3M`, `YTD`...).
- `select-multiple` and `suggest-multiple` that show a summary or chips.
- Suggests that group their options.
- A `map` element (Leaflet with OpenStreetMap) that shows the rows of a query as markers.

## Security

- Passwords stored as **BCrypt** hashes, rehashed at the next login, and a required master key for stored secrets.
- A **security audit** of the security events, with its own screen.
- **Permissions** and access by screen, server-only queries and maintain targets, and HTTP status codes for refused
  actions and expired sessions.
- HTML of the React grid cells sanitized.

## Tested on real databases

The integration tests of MySQL, PostgreSQL, SQL Server and Oracle run their database in Testcontainers, locally and in
CI: Docker is the only requirement.

## Upgrading

1. Upgrade to the latest **4.x** release and fix its deprecation warnings. AWE 4 stays maintained on the `support/4.x`
   line, see [Release Lines and Support](/docs/guides/release-lines-and-support).
2. Follow the [AWE 5 migration guide](/docs/guides/v5-migration) and its upgrade checklist.
3. Tell us how it goes on [GitLab](https://gitlab.com/aweframework/awe/-/issues).

The full list of changes is in the [CHANGELOG](https://gitlab.com/aweframework/awe/-/blob/master/CHANGELOG.md).
