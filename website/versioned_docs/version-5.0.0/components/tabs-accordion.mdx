Both organise a dense screen into parts. **Tabs** show one part at a time and keep the list of parts always in view; an **accordion**
stacks the parts as collapsible sections, one or several open. Below are the real components of the AWE React client: click on them.

## Tabs {#tabs}

A `tab` holds one `tabcontainer` per page. The list of tabs comes from an enumerated list or a query of the server (`initial-load` and
`target-action`) and the value of each option is the `id` of its tabcontainer. Here the stage fills that list with a static one.

<AwePlayground spec={tabs} />

## Accordion {#accordion}

An `accordion` holds `accordion-item` elements, each with a `label` for its header. By default (`autocollapse="true"`) opening an item
closes the others.

## Recipes {#recipes}

### Form split into tabs {#recipe-tabs-form}

Each tabcontainer holds any component. A tab with an invalid field is marked in the list, so the user knows where to look.

<AweLive
  components={{
    form: {model: {values: [{value: 'person', label: 'Person', selected: true}, {value: 'company', label: 'Company'}]}},
    Name: {attributes: {label: 'Name', placeholder: 'Full name'}},
    Email: {attributes: {label: 'Email', icon: 'lucide:mail'}},
    Company: {attributes: {label: 'Company name'}},
    Size: {attributes: {label: 'Employees'}},
  }}
  nodes={[{elementType: 'Tab', id: 'form', elementList: [
    {elementType: 'TabContainer', id: 'person', elementList: [
      {elementType: 'Criteria', component: 'text', id: 'Name'},
      {elementType: 'Criteria', component: 'text', id: 'Email'},
    ]},
    {elementType: 'TabContainer', id: 'company', elementList: [
      {elementType: 'Criteria', component: 'text', id: 'Company'},
      {elementType: 'Criteria', component: 'numeric', id: 'Size'},
    ]},
  ]}]}
/>

```xml
<tab id="form" initial-load="enum" target-action="FormTabs">
  <tabcontainer id="person">
    <criteria id="Name" component="text" label="Name" placeholder="Full name" />
    <criteria id="Email" component="text" label="Email" icon="lucide:mail" />
  </tabcontainer>
  <tabcontainer id="company">
    <criteria id="Company" component="text" label="Company name" />
    <criteria id="Size" component="numeric" label="Employees" />
  </tabcontainer>
</tab>
```

### Accordion with several sections open {#recipe-accordion-multiple}

`autocollapse="false"` lets the user keep several sections open at the same time, to compare them.

<AweLive
  components={{faq: {attributes: {autocollapse: false}}}}
  nodes={[{elementType: 'Accordion', id: 'faq', elementList: [
    {elementType: 'AccordionItem', id: 'what', label: 'What is a criterion?', elementList: [
      {elementType: 'Tag', type: 'p', label: 'An input of a screen: it gets a value from the user and sends it to the server.'},
    ]},
    {elementType: 'AccordionItem', id: 'where', label: 'Where do the options come from?', elementList: [
      {elementType: 'Tag', type: 'p', label: 'From an enumerated list or a query of the server.'},
    ]},
  ]}]}
/>

```xml
<accordion id="faq" autocollapse="false">
  <accordion-item id="what" label="What is a criterion?">
    <tag type="p" label="An input of a screen: it gets a value from the user and sends it to the server." />
  </accordion-item>
  <accordion-item id="where" label="Where do the options come from?">
    <tag type="p" label="From an enumerated list or a query of the server." />
  </accordion-item>
</accordion>
```

## Events and actions {#events-and-actions}

Neither has an event of its own. The user picks the tab or the section; to do it from the screen, a [dependency](../api/dependencies.md)
changes the `selected` attribute of an accordion with the id of the item to open (see
[the accordion](../api/accordion.md#dependencies)), and a `variable` makes a screen open on a given tab. A tabcontainer with
`deferred="true"` loads its data the first time its tab is shown.
