El equipo de AWE framework se enorgullece de anunciar **AWE 5.0**, la mayor versión del framework hasta la fecha: una
plataforma nueva (Java 21, Spring Boot 4.1, Jackson 3), un sistema de diseño nuevo compartido por los dos motores web,
el motor React como motor para el trabajo nuevo y una nueva generación de pantallas de administración, grids y
herramientas de seguridad.

Antes de actualizar, lea la [guía de migración a AWE 5](/docs/guides/v5-migration): enumera todo lo que una aplicación
AWE 4 debe revisar, con el síntoma, qué hacer y dónde leer más.

## Una plataforma nueva

| | AWE 4 | AWE 5 |
|---|---|---|
| Java | 17 | **21** |
| Spring Boot | 3.5 | **4.1** (Spring Framework 7, Spring Security 7, JUnit 6, Flyway 11) |
| Jackson | 2.x | **3** (`tools.jackson`) |
| Cliente React | `2.x`, línea de versiones propia | La misma versión que el framework, React 19 |
| Gráficos | Highcharts | **Apache ECharts** en los dos motores |

El cliente React (`awe-react-client`) sigue ahora la versión del framework, así que un solo número indica qué está
ejecutando. Sus paquetes pesados (gráficos, editores, mapas) se cargan bajo demanda, y el cliente AngularJS ya no
incluye el JavaScript de Bootstrap 3.

## El sistema de diseño de AWE 5

Los dos motores web comparten un único sistema de diseño: tipografía Inter, iconos Lucide, modos claro y oscuro,
densidad cómoda y compacta y temas formados por un **color primario** y una **superficie**. Un tema es un nombre de
paleta o un color hexadecimal, y toda la escala se genera a partir de él con un contraste legible. La nueva pantalla
`theme-admin` muestra una vista previa en vivo del tema mientras se edita.

El [sistema de diseño](/docs/design-system/overview) está documentado en este sitio con componentes en vivo.

## React, el motor para el trabajo nuevo

El motor React es el motor de AWE 5: los componentes nuevos llegan a él. El motor AngularJS sigue funcionando, así que
sus aplicaciones funcionan tal como están, pero queda congelado: recibe correcciones, no componentes nuevos. Una misma
pantalla XML sigue funcionando en los dos motores.

## Nuevas pantallas de administración

El menú por defecto abre una nueva generación de pantallas de administración, todas construidas igual: un grid con
búsqueda y filtros rápidos con contadores, acciones por fila, una barra de selección y un panel lateral para crear y
editar.

- `user-admin`, `profile-admin`, `site-admin`, `module-admin`, `database-admin`, `theme-admin`
- `email-server-admin`, `queue-admin`, `sequence-admin`, `application-parameter-admin`
- `access-admin`: todo el menú como un árbol con el acceso efectivo de cada opción para un perfil o un usuario, la
  capa que lo decide, *¿Por qué?*, *Comparar*, *Revisar* y *Vista previa*.

Las pantallas antiguas quedan obsoletas y se eliminarán en la 5.1.0.

## Grids que hacen más

- Una barra de herramientas en cada grid: un diálogo de **Columnas** (mostrar, ocultar y reordenar, guardado por
  usuario) y **Maximizar**.
- **Agrupar** por una o varias columnas, con subtotales y agregados.
- **Búsquedas guardadas**, con una búsqueda por defecto por usuario o por perfil.
- Celdas más ricas: una línea secundaria, un estado con un punto de color, chips, barras de datos y texto que se
  ajusta.
- Grids en árbol con selección múltiple y filas que se mueven con el teclado.

## Nuevos criterios y elementos

- `date-range` con rangos rápidos (`1M`, `3M`, `YTD`...).
- `select-multiple` y `suggest-multiple` que muestran un resumen o chips.
- Suggests que agrupan sus opciones.
- Un elemento `map` (Leaflet con OpenStreetMap) que muestra las filas de una consulta como marcadores.

## Seguridad

- Contraseñas guardadas como hashes **BCrypt**, que se recalculan en el siguiente inicio de sesión, y una clave maestra
  obligatoria para los secretos guardados.
- Una **auditoría de seguridad** de los eventos de seguridad, con su propia pantalla.
- **Permisos** y acceso por pantalla, consultas y destinos de mantenimiento solo de servidor, y códigos de estado HTTP
  para las acciones rechazadas y las sesiones caducadas.
- HTML de las celdas de los grids de React saneado.

## Probado en bases de datos reales

Las pruebas de integración de MySQL, PostgreSQL, SQL Server y Oracle ejecutan su base de datos en Testcontainers, en
local y en CI: Docker es el único requisito.

## Actualizar

1. Actualice a la última versión **4.x** y corrija sus avisos de obsolescencia. AWE 4 sigue mantenido en la línea
   `support/4.x`; consulte [Líneas de versión y soporte](/docs/guides/release-lines-and-support).
2. Siga la [guía de migración a AWE 5](/docs/guides/v5-migration) y su lista de comprobación.
3. Cuéntenos cómo le va en [GitLab](https://gitlab.com/aweframework/awe/-/issues).

La lista completa de cambios está en el [CHANGELOG](https://gitlab.com/aweframework/awe/-/blob/master/CHANGELOG.md).
