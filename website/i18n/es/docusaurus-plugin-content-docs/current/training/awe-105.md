El módulo developer ofrece herramientas de ayuda para las tareas de mantenimiento habituales de AWE. En la práctica, el flujo más visible es la gestión de literales: se define una vez la raíz de los XML y después se pueden añadir, modificar, traducir o eliminar literales sin editar a mano cada fichero.

## Ruta rápida {#quick-path}

1. Añade la dependencia del starter developer.
2. Activa el módulo en `application.properties`.
3. Añade las opciones de menú de developer.
4. Configura la ruta raíz de los XML.
5. Usa el gestor de literales para crear, modificar, traducir y eliminar.

## Antes de empezar {#before-you-start}

Este módulo es más útil cuando ya tienes una estructura de aplicación funcionando y algunos ficheros de literales que gestionar.

Si todavía no has creado pantallas ni claves de literales, revisa primero [awe-102](./awe-102.md).

## Paso 1: Activar el módulo developer {#step-1-enable-the-developer-module}

Añade la dependencia en `pom.xml`:

```xml title="pom.xml"
<dependency>
  <groupId>com.almis.awe</groupId>
  <artifactId>awe-developer-spring-boot-starter</artifactId>
</dependency>
```

Activa el módulo en `application.properties` añadiendo `awe-developer` a tu lista de módulos actual:

```properties title="application.properties"
# Keep your current application-specific modules.
# Add awe-developer alongside the modules you already use.
awe.application.module-list=<your-existing-modules>,awe-developer
```

Expónlo a través del menú:

```xml title="public.xml or private.xml"
<option name="developer" label="MENU_DEVELOPER" icon="paint-brush">
  <option name="path-manager" label="MENU_PATH" screen="path-manager" icon="terminal"/>
  <option name="local-manager" label="MENU_LANGUAGES" screen="local-manager" icon="language"/>
</option>
```

<img alt="Opciones de developer" src={require('@docusaurus/useBaseUrl').default('img/training/path-option.png')} />

## Paso 2: Configurar la ruta raíz de los XML {#step-2-configure-the-xml-root-path}

Antes de poder editar los descriptores de tu aplicación, las herramientas necesitan la ruta raíz donde están los ficheros XML de la aplicación.

<img alt="Selección de ruta" src={require('@docusaurus/useBaseUrl').default('img/training/path.png')} />

Indica al módulo la raíz que contiene las carpetas de la aplicación:

<img alt="Carpetas" src={require('@docusaurus/useBaseUrl').default('img/training/folders.png')} />

Es decir, la ruta configurada debe ser la ubicación padre de carpetas como `global/`, `locale/`, `menu/` y `screen/`.

## Paso 3: Usar el gestor de literales {#step-3-use-the-locale-manager}

El gestor de literales es el flujo más habitual del módulo developer. Ayuda a añadir, modificar, traducir y eliminar literales en toda la aplicación.

<img alt="Gestión de literales" src={require('@docusaurus/useBaseUrl').default('img/training/lit-man.png')} />

Los cambios afectan tanto al estado en memoria como a los ficheros XML subyacentes, por lo que en muchos casos basta con recargar la página, sin reiniciar el servidor de aplicaciones, tras un cambio que solo afecte a literales.

El gestor también se integra con una API de traducción para ofrecer un borrador inicial de traducción en los idiomas configurados. Considera ese resultado un punto de partida y revísalo antes de conservarlo.

La zona de búsqueda normalmente permite:

- elegir el idioma con el que trabajas
- buscar entre las claves de literales existentes

<img alt="Criterios de búsqueda" src={require('@docusaurus/useBaseUrl').default('img/training/search-lite.png')} />

### Añadir un literal {#add-a-locale}

Pulsa **New** en la lista de literales:

<img alt="Lista de literales" src={require('@docusaurus/useBaseUrl').default('img/training/lit-list.png')} />

Después indica:

- el código del literal (identificador único)
- el texto en el idioma seleccionado actualmente en el gestor

<img alt="Alta de literal" src={require('@docusaurus/useBaseUrl').default('img/training/new-lit.png')} />

Al añadir un literal, el módulo lo crea para todos los idiomas definidos en la aplicación. Revisa las traducciones generadas antes de darlas por definitivas.

### Modificar un literal {#modify-a-locale}

Al seleccionar un literal se muestran las traducciones existentes de esa clave.

<img alt="Lista de literales en distintos idiomas" src={require('@docusaurus/useBaseUrl').default('img/training/translation-list.png')} />

Después puedes actualizar el valor del idioma seleccionado:

<img alt="Modificación del valor" src={require('@docusaurus/useBaseUrl').default('img/training/text-trans.png')} />

Si lo necesitas, cambia a la pestaña **Markdown** para editar el valor como Markdown en lugar de texto plano:

<img alt="Modificación del valor en Markdown" src={require('@docusaurus/useBaseUrl').default('img/training/markdown-trans.png')} />

Para solicitar una traducción automática, elige los idiomas de origen y destino y pulsa **Translate**. Guarda el resultado final con **Update**.

### Eliminar un literal {#delete-a-locale}

Selecciona el literal y pulsa **Delete** para eliminarlo de los idiomas disponibles.

## Qué hacer a continuación {#what-to-do-next}

- Vuelve a [awe-102](./awe-102.md) cuando necesites añadir nuevas etiquetas de pantalla.
- Vuelve a [awe-101](./awe-101.md) si necesitas un recordatorio de la estructura del proyecto generado.
- Trata el módulo developer como un acelerador, no como un sustituto de entender cómo se organizan los ficheros XML subyacentes.
